## 1. 认证模块（黑盒）

| 用例名称 | 前置条件 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| AUTH-01 正常登录 | 数据库已重置；SG900001 未锁定 | `POST /api/auth/login`，Body 为 `{"account":"SG900001","password":"123456"}` | `code=0`；返回 `sessionId`；`permissions.length=20`；`menus.length=7`；会话到期时间为当日 `23:59:59` |
| AUTH-02 密码错误 | SG000102 未锁定 | 使用 SG000102 和错误密码登录 | `code=401`；返回剩余尝试次数；不返回 `sessionId` |
| AUTH-03 连续失败锁定 | 使用 Newman 本轮新建的唯一测试账号 | 连续提交 5 次错误密码 | 第 1 至 4 次 `code=401`；第 5 次 `code=429`；等待期间即使密码正确仍为 `code=429` |
| AUTH-04 当前用户 | 已取得管理员 sessionId | `GET /api/auth/me`，携带 Bearer Token | 返回管理员用户信息、20 枚权限和 7 个菜单 |
| AUTH-05 登出 | 已登录 | `POST /api/auth/logout` | `code=0`；原 Token 再访问受保护接口返回 401 |

登录锁定状态保存在 `LoginGuard` 的进程内 `ConcurrentHashMap` 中。重启后端会清空锁定状态；数据库重置不会清空进程内计数。Postman 集合的锁定用例使用每轮新建的临时账号，避免污染张伟等固定测试账号。

### 3.3 审批写入位置

| 申请目标 | 审批通过后的写入表 | 生效方式 |
| --- | --- | --- |
| 角色 `ROLE` | `sys_user_role` | 撤销申请人会话；重新登录后按新角色合并权限 |
| 权限 `PERM` | `sys_user_permission` | 撤销申请人会话；重新登录后按直接权限合并生效 |

SELECT id, applicant_id, target_type, target_id, status, approver_id,

## 5. JaCoCo 覆盖率报告

`pom.xml` 已配置 `jacoco-maven-plugin 0.8.12`：

- `prepare-agent` 在测试 JVM 启动前注入覆盖率代理；
- `report` 绑定在 `test` 阶段，测试完成后生成 HTML/XML。

生成命令：

```powershell
& 'C:\Users\27642\Maven\apache-maven-3.10.0\bin\mvn.cmd' clean test
```

报告位置：

| 文件 | 用途 |
| --- | --- |
| `target/site/jacoco/index.html` | 总览入口，浏览器直接打开 |
| `target/site/jacoco/jacoco.xml` | CI 或 SonarQube 可读取的机器数据 |
| `target/site/jacoco/com.iam.*/index.html` | 按包、类、方法下钻 |

指标含义：

| 指标 | 含义 |
| --- | --- |
| Instructions | JVM 字节码指令命中比例，粒度最细 |
| Branches | `if/else`、循环、逻辑表达式的分支覆盖比例 |
| Lines | 可执行代码行命中比例 |
| Methods | 至少执行一次的方法比例 |
| Classes | 至少执行一个方法的类比例 |

颜色说明：

- 绿色：已覆盖；
- 黄色：部分覆盖，例如只执行了 `if` 的一个分支；
- 红色：未覆盖。

一期以核心业务类为白盒重点：`LoginGuard`、`AuthService`、`ApplyService`。Controller 与 Mapper 的完整数据库路径由 Newman 集成测试覆盖，因此总覆盖率不应只按 Controller 数量判断。
