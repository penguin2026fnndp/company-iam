# 功能清单（F01–F28）

## 一、权限码规范

一个权限码 = **一个功能点上的一个操作**，格式为 `资源:动作`，跨系统时用 `系统:资源:动作`。

| 动作 | 编码 | 示例 |
| --- | --- | --- |
| 查看 | VIEW | `USER:VIEW`、`FIN:RPT:VIEW` |
| 新增 | ADD | `USER:ADD` |
| 编辑 | EDIT | `ROLE:EDIT` |
| 删除 | DELETE | `USER:DELETE` |
| 导出 | EXPORT | `FIN:RPT:EXPORT` |
| 分配角色 | ASSIGN_ROLE | `USER:ASSIGN_ROLE` |
| 分配权限 | ASSIGN_PERM | `ROLE:ASSIGN_PERM` |
| 审批 | APPROVE | `APPLY:APPROVE` |

菜单、页面、按钮、接口都引用同一个码，不维护第二份清单。

## 二、功能表

| 编号 | 功能 | 接口 | 权限码 | 关键规则 | 主要异常 |
| --- | --- | --- | --- | --- | --- |
| F01 | 登录 | `POST /api/auth/login` | 无 | 校验账号密码；停用账号拒绝；成功写会话 | 401 账号或密码错误；403 账号停用 |
| F02 | 登出 | `POST /api/auth/logout` | 登录即可 | 删除当前会话 | 401 未登录 |
| F03 | 当前用户 | `GET /api/auth/me` | 登录即可 | 返回用户、角色、权限码、菜单 | 401 |
| F04 | 用户列表 | `GET /api/users` | `USER:VIEW` | 账号/姓名模糊搜索，分页 | 403 |
| F05 | 用户详情 | `GET /api/users/{id}` | `USER:VIEW` | 含角色与权限预览 | 404 |
| F06 | 新增用户 | `POST /api/users` | `USER:ADD` | 账号唯一；初始密码 123456；创建后无角色 | 409 账号重复；400 缺字段 |
| F07 | 修改用户 | `PUT /api/users/{id}` | `USER:EDIT` | 只改姓名、手机号 | 404 |
| F08 | 启用/停用 | `PUT /api/users/{id}/status` | `USER:EDIT` | 停用立刻踢会话；不能停用自己 | 400 停用自己 |
| F09 | 重置密码 | `PUT /api/users/{id}/password` | `USER:EDIT` | 重置为 123456，旧会话失效 | 404 |
| F10 | 删除用户 | `DELETE /api/users/{id}` | `USER:DELETE` | 不能删自己；级联删角色关系与会话 | 400 删除自己 |
| F11 | 查看用户角色 | `GET /api/users/{id}/roles` | `USER:VIEW` | 返回全部角色 + 是否已勾选 | 404 |
| F12 | 分配角色 | `PUT /api/users/{id}/roles` | `USER:ASSIGN_ROLE` | 覆盖式保存；事务；保存后踢会话 | 400 角色不存在 |
| F13 | 角色列表 | `GET /api/roles` | `ROLE:VIEW` | 带成员数、权限数 | 403 |
| F14 | 角色详情 | `GET /api/roles/{id}` | `ROLE:VIEW` | 编码、名称、备注、状态 | 404 |
| F15 | 新增角色 | `POST /api/roles` | `ROLE:ADD` | 编码唯一、大写字母开头 | 409 编码重复 |
| F16 | 修改角色 | `PUT /api/roles/{id}` | `ROLE:EDIT` | 名称、备注、启停；停用踢持有人会话 | 404 |
| F17 | 删除角色 | `DELETE /api/roles/{id}` | `ROLE:DELETE` | 仍有成员时拒绝 | 409 仍有成员 |
| F18 | 查看角色权限 | `GET /api/roles/{id}/permissions` | `ROLE:VIEW` | 按系统/模块分组，带勾选状态 | 404 |
| F19 | 保存角色权限 | `PUT /api/roles/{id}/permissions` | `ROLE:ASSIGN_PERM` | 覆盖式；事务；踢持有人会话 | 400 权限不存在 |
| F20 | 权限目录 | `GET /api/permissions` | `PERM:VIEW` | 按系统筛选、关键字查询 | 403 |
| F21 | 提交权限申请 | `POST /api/applies` | 登录即可 | 申请角色或单个权限，校验重复与在办单 | 400/404/409 |
| F22 | 我的申请 / 待办 | `GET /api/applies/mine`、`GET /api/applies?status=0` | 本人 / `APPLY:APPROVE` | 申请人看自己的单；管理员看待办 | 403 |
| F23 | 审批 | `PUT /api/applies/{id}/decide` | `APPLY:APPROVE` | 通过后自动写角色关系或直接权限，并踢会话 | 400/404/409 |
| F24 | 新增权限点 | `POST /api/permissions` | `PERM:ADD` | 权限码唯一；新增后可在角色矩阵勾选 | 400/409 |
| F25 | 删除权限点 | `DELETE /api/permissions/{id}` | `PERM:DELETE` | 物理删除，角色权限与直接权限级联解除 | 404 |
| F26 | 查询用户直接权限 | `GET /api/users/{id}/permissions` | `USER:EDIT` | 只返回 `sys_user_permission` 中的直接授权 | 403/404 |
| F27 | 全量覆盖直接权限 | `POST /api/users/{id}/permissions` | `USER:EDIT` | 先清空再批量写入；成功后强制该用户下线 | 400/403/404 |
| F28 | 剥夺单条直接权限 | `DELETE /api/users/{id}/permissions/{permId}` | `USER:EDIT` | 删除一条直接权限并强制该用户下线 | 403/404 |

> F03 同时承载"我的权限"：权限集合在此接口计算并下发，不单独开接口，避免两处口径。

## 五、本次不做

多级审批（本版为"一人审批即生效"）、差量、项目域、组织树、审计报表、角色继承（RBAC1）、互斥约束（RBAC2）、数据权限（本人/本部门）。

> 说明：申请审批已在本版实现（F21–F23）。审批通过后的"直接权限"写入 `sys_user_permission`，等价于 v0.5 里"例外授予"的最小版本；但没有有效期、没有转岗失效、没有多级审批链。
