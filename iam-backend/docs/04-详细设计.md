# 详细设计（功能分解 · F01–F20）

> 版本：2026-10-19 · 与 `src/main/java/com/iam` 下的实现逐条对应
> 用法：一张卡 = 一个功能；卡片里的"验收用例"可以直接改成 Postman/Apifox 用例。

## 0. 阅读说明

- 每张卡固定 9 个字段：接口、权限、入参、校验、出参、Controller、Service、Mapper、异常、用例。
- 代码包：`auth` / `user` / `role` / `permission` / `report`，公共能力在 `common`。
- 所有接口前缀 `/api`，除登录外都要 `Authorization: Bearer <sessionId>`。
- 统一返回：`{ code, data, message }`，`code = 0` 为成功。

## 1. 公共约定

### 1.1 错误码

| code | 含义 | 典型场景 |
| --- | --- | --- |
| 0 | 成功 | — |
| 400 | 参数或业务规则不满足 | 工号格式错误、停用自己、删除自己、角色编码非法 |
| 401 | 未登录或会话失效 | 无 token、token 过期、会话被撤销 |
| 403 | 已登录但无权限 | 缺 `USER:VIEW`、账号已停用 |
| 404 | 资源不存在 | 用户/角色 id 不存在 |
| 409 | 唯一键冲突或存在引用 | 工号重复、角色编码重复、角色仍有成员 |
| 500 | 未预期异常 | SQL 执行失败等 |

### 1.2 鉴权

1. `AuthInterceptor` 解析 `Authorization: Bearer <token>`；
2. 查 `sys_session`：未撤销、未过期、用户启用，否则 401；
3. 用 `PermissionMapper.codesOf(userId)` 取权限集合放进 `SessionContext`；
4. 读方法上的 `@RequirePerm`，缺权限直接写 403，响应体带 `requiredPerm`。

### 1.3 权限码

`资源:动作`，跨系统用 `系统:资源:动作`。动作仅七种：
`VIEW / ADD / EDIT / DELETE / EXPORT / ASSIGN_ROLE / ASSIGN_PERM`。

## 2. 功能卡

### F01 登录

| 项 | 内容 |
| --- | --- |
| 接口 | `POST /api/auth/login` |
| 权限 | 匿名 |
| 入参 | `account`（工号）、`password` |
| 校验 | 两项非空；未处于锁定期；账号存在；BCrypt 匹配；`status = 1` |
| 出参 | `sessionId`、`expireAt`、`user`、`roles[]`、`permissions[]`、`menus[]` |
| Controller | `AuthController.login` |
| Service | `AuthService.login`：查锁定 → 校验密码 → UUID → 写会话 → 组装 profile |
| Mapper | `UserMapper.findByAccount`、`SessionMapper.create`、`PermissionMapper.codesOf` |
| 异常 | 400 空参数；401 账号或密码错误；403 账号停用；429 连续失败 5 次锁定 15 分钟 |
| 用例 | ① `SG900001/123456` → code 0、18 枚权限；② 错密码 → 401 且提示剩余次数；③ 停用账号 → 403；④ 空密码 → 400；⑤ 连续 5 次错误 → 第 5 次返回 429，15 分钟内再登录仍 429 |

## 4. 设计—实现差异（已处理）

2026-10-19 按评审意见全部处理：

| # | 差异 | 处理结果 |
| --- | --- | --- |
| 1 | 登录失败 5 次锁定 | **已实现**：`LoginGuard` 用 `ConcurrentHashMap` 计数，第 5 次失败返回 429 并锁定 15 分钟；登录成功清零。生产可平滑替换为 Redis |
| 2 | 查用户角色未校验用户 | **已实现**：`UserService.rolesOf` 先查用户，不存在返回 404 |
| 3 | 分配角色 / 保存权限传非法 id | **已实现**：Service 先校验 id 存在性，不存在抛 `IllegalArgumentException`，全局异常转 400 |
| 4 | 权限变更审计 | **一期不落库**：分配角色、保存角色权限、停用、重置密码各打一条 `AUDIT ...` 的 INFO 日志；二期补 `sys_audit_log` |
| 5 | 无在线接口文档 | **已接入** springdoc-openapi 2.8.5，Controller 均有 `@Tag` / `@Operation` |

### 4.1 审计口径（一期）

一期暂不实现审计日志落库，仅打印 INFO 级别日志。控制台输出即"留痕"，不入库、不可检索；检查时按此说明，不承诺审计报表与检索能力。

日志格式：
