# 数据设计（真实组织数据 + 三权分立 · 10 张表）

## 1. 数据来源

| 文件 | 用途 |
| --- | --- |
| `datas/市政公司部门信息表.xlsx` | 111 个部门节点与部门经理 |
| `datas/市政公司员工信息表.xlsx` | 10,000 名真实员工，从中选取 10 名代表 |
| `datas/市政公司应用软件功能权限清单(1).xlsx` | 18 个系统、359 个功能点；导入前 3 个系统 |

初始化结果：

| 项目 | 数量 |
| --- | ---: |
| 部门 | 111 |
| 代表员工 | 10 |
| 角色 | 7 |
| 业务系统 | 3 |
| 业务功能点 | 42 |
| IAM 管理权限 | 22 |
| 业务权限 | 252 |
| 权限总数 | 274 |

## 2. 表关系

```text
sys_department(parent_id) ──┬─ parent / children 自关联
                           └─< sys_user.department_id

sys_user ──< sys_user_role >── sys_role
sys_user ──< sys_session
sys_user ──< sys_user_permission >── sys_permission
sys_role ──< sys_role_permission >── sys_permission
sys_user ──< sys_permission_apply >── approver(sys_user)
```

用户有效权限：

```text
所有启用角色权限的并集 ∪ 用户直接权限
```

## 3. 核心表

### 3.1 sys_department

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT UNSIGNED PK | 部门 ID |
| parent_id | BIGINT UNSIGNED FK | 上级部门，根节点总公司为 NULL |
| name | VARCHAR(128) | 部门全称 |
| manager_id | BIGINT UNSIGNED | 部门经理用户 ID；不建外键以避免循环依赖 |
| created_at / updated_at | DATETIME | 时间戳 |

索引与约束：

- `uk_dept_parent_name(parent_id, name)`；
- `idx_dept_parent(parent_id)`；
- `idx_dept_manager(manager_id)`；
- `fk_dept_parent` 自关联，删除上级时置空。

部门树示例：

```text
总公司
├─ 综合办公室
├─ 人力资源部
├─ 工程技术部
├─ 道路工程分公司
│  ├─ 道路工程分公司-综合办公室
│  └─ 道路工程分公司-第一项目经理部
└─ 市政养护分公司
   └─ 市政养护分公司-第四项目经理部
```

### 3.2 sys_user

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT UNSIGNED PK | 用户 ID |
| account | VARCHAR(32) UNIQUE | 真实 SG 工号 |
| name | VARCHAR(64) | 真实姓名 |
| phone | VARCHAR(20) | 真实手机号 |
| password_hash | VARCHAR(100) | BCrypt，种子密码统一 123456 |
| status | TINYINT | 1 启用 / 0 停用 |
| department_id | BIGINT UNSIGNED FK | 所属部门 |

选择 10 名员工覆盖总公司、3 个分公司和多个部门层级，详见 `README.md`。

### 3.3 sys_role

| ID | code | 角色 | 数据边界 |
| ---: | --- | --- | --- |
| 1 | SYS_ADMIN | 系统管理员 | USER:*、DEPT:*、PERM:*，无业务和 ROLE 权限 |
| 2 | SEC_ADMIN | 安全管理员 | ROLE:*、APPLY:APPROVE，无用户管理和业务权限 |
| 3 | AUDITOR | 审计管理员 | 全局只读 VIEW |
| 4 | LEADER | 公司领导 | Excel 公司领导列，52 枚业务权限 |
| 5 | MGR | 部门经理 | Excel 部门经理列，67 枚业务权限 |
| 6 | PM | 项目经理 | Excel 项目经理列，51 枚业务权限 |
| 7 | EMP | 普通员工 | Excel 普通员工列，43 枚业务权限 |
| 8 | SUPER_ADMIN | 超级管理员 | 全部 274 枚管理权限与业务权限 |

### 3.4 sys_permission

权限码格式：

```text
系统编码:模块编码:功能编号:动作
```

示例：

```text
OA:DOC:F003:VIEW
OA:DOC:F003:ADD
OA:DOC:F003:EDIT
OA:DOC:F003:DELETE
OA:DOC:F003:EXPORT
OA:DOC:F003:APPROVE
```

前三系统：

| 系统 | 系统编码 | 功能点 | 权限数 |
| --- | --- | ---: | ---: |
| OA 协同办公系统 | OA | 18 | 108 |
| 企业即时通讯系统 | IM | 12 | 72 |
| 企业知识库管理系统 | KM | 12 | 72 |

每个功能点生成 VIEW、ADD、EDIT、DELETE、EXPORT、APPROVE 六类操作。

### 3.5 关联与业务表

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `sys_user_role` | user_id, role_id | 用户角色多对多 |
| `sys_role_permission` | role_id, permission_id | 角色权限多对多 |
| `sys_user_permission` | user_id, permission_id, apply_id | 个人例外或审批结果；种子阶段为空 |
| `sys_session` | id, user_id, expire_at, revoked_at | Bearer Token 会话 |
| `sys_permission_apply` | applicant_id, target_type, target_id, status | ROLE/PERM 申请与审批 |
| `sys_audit_log` | operator_id, action, target_user_id, detail | 角色变更与审批结果审计 |

## 4. 种子授权规则

1. Excel 五个岗位列逐行解析为动作集合；
2. “全部”展开为 VIEW/ADD/EDIT/DELETE/EXPORT/APPROVE；
3. “查看/编辑/审批”等组合按 `/` 拆分为独立权限；
4. SYS_ADMIN 只获得 13 枚用户/部门/权限管理；SEC_ADMIN 只获得 7 枚角色与审批权限；
5. LEADER/MGR/PM/EMP 分别获得 52/67/51/43 枚业务权限，SUPER_ADMIN 获得全部 274 枚；
6. 业务权限只写入 `sys_role_permission`；
7. `sys_user_permission` 在种子阶段清空，不向任何员工直接授予业务 VIEW。

## 5. 初始化顺序

`db/seed.sql` 严格按以下顺序写入：

```text
部门 → 角色 → 权限 → 员工 → 用户角色 → 角色权限 → 清空用户直接权限
```

部门经理字段不建立到用户的外键，因此可以先插部门；其余关系均满足外键顺序。
