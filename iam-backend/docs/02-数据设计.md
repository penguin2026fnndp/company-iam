# 数据设计（RBAC0 + 申请审批 · 8 张表）

## 一、总览

| # | 表 | 中文 | 行数级 | 作用 |
| --- | --- | --- | --- | --- |
| 1 | `sys_user` | 用户 | 万级 | 只存身份，不存权限 |
| 2 | `sys_role` | 角色 | 百级 | 权限包，可启停 |
| 3 | `sys_permission` | 权限 | 千级 | 功能点 × 操作，一行一个权限码 |
| 4 | `sys_user_role` | 用户角色 | 万级 | 用户与角色的多对多 |
| 5 | `sys_role_permission` | 角色权限 | 万级 | 角色与权限的多对多 |
| 6 | `sys_session` | 会话 | 万级 | 登录后签发，接口据此识别当前用户 |
| 7 | `sys_user_permission` | 用户直接权限 | 千级 | 审批通过后写入的单条权限（例外授予） |
| 8 | `sys_permission_apply` | 权限申请单 | 万级 | 申请人、目标、理由、状态、审批人、审批时间 |

## 二、关系图

```
                 ┌──────────────┐
                 │  sys_user    │
                 └──────┬───────┘
       1                │ 1
        │                │
       N│                │N
┌──────▼────────┐   ┌───▼──────────────┐
│ sys_user_role │   │  sys_session     │
└──────┬────────┘   └──────────────────┘
       │N                    （会话只属于一个用户）
       │
     1 │
┌──────▼────────┐
│  sys_role     │
└──────┬────────┘
       │1
       │
      N│
┌──────▼────────────────┐
│ sys_role_permission   │
└──────┬────────────────┘
       │N
       │
     1 │
┌──────▼──────────────┐
│  sys_permission     │
└─────────────────────┘
```

一句话：**用户通过角色持有权限**。用户挂角色，角色挂权限，两项都是多对多，最终权限取并集；审批通过的单条权限是唯一的例外（见 3.7）。

## 三、表结构

### 3.1 sys_user 用户

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT UNSIGNED PK | 自增 |
| account | VARCHAR(32) | 工号，唯一，创建后不可改 |
| name | VARCHAR(32) | 姓名 |
| phone | VARCHAR(20) | 手机号，可空 |
| password_hash | VARCHAR(100) | BCrypt（cost 10，60 字符） |
| status | TINYINT | 1 启用 / 0 停用 |
| created_at / updated_at | DATETIME | 自动维护 |

索引：`uk_user_account(account)`。**没有** role_id、没有 perm 字段。

### 3.2 sys_role 角色

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| code | VARCHAR(32) | 角色编码，唯一，大写字母开头，不可改 |
| name | VARCHAR(32) | 角色名称 |
| remark | VARCHAR(255) | 备注 |
| status | TINYINT | 1 启用 / 0 停用 |
| created_at / updated_at | DATETIME | |

索引：`uk_role_code(code)`。

### 3.3 sys_permission 权限

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| sys_code | VARCHAR(16) | 系统编码：IAM / OA / FIN / PM |
| sys_name | VARCHAR(32) | 系统名称，用于分组展示 |
| module_name | VARCHAR(32) | 模块，如"用户管理" |
| func_code | VARCHAR(32) | 功能点编码，如 USER、FIN:RPT |
| func_name | VARCHAR(64) | 功能点名称，如"用户" |
| action | VARCHAR(16) | VIEW/ADD/EDIT/DELETE/EXPORT/ASSIGN_ROLE/ASSIGN_PERM |
| perm_code | VARCHAR(64) | 权限码，唯一，如 `USER:VIEW` |
| status | TINYINT | 1 启用 |
| sort_no | INT | 展示排序 |

索引：`uk_perm_code(perm_code)`、`uk_perm_func_action(sys_code, func_code, action)`。

### 3.4 sys_user_role 用户角色

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id | BIGINT PK | 外键 → sys_user.id |
| role_id | BIGINT PK | 外键 → sys_role.id |
| created_at | DATETIME | |

联合主键 `(user_id, role_id)` 天然去重；两个外键都 `ON DELETE CASCADE`。

### 3.5 sys_role_permission 角色权限

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| role_id | BIGINT PK | 外键 → sys_role.id |
| permission_id | BIGINT PK | 外键 → sys_permission.id |
| created_at | DATETIME | |

联合主键 `(role_id, permission_id)`，级联删除。

### 3.6 sys_session 会话

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | CHAR(36) PK | UUID，即 Bearer Token |
| user_id | BIGINT | 外键 → sys_user.id，级联删除 |
| issued_at | DATETIME | 签发时间 |
| expire_at | DATETIME | 当日 23:59:59 |
| revoked_at | DATETIME NULL | 主动失效时间（停用、改角色、重置密码） |
| ip / user_agent | VARCHAR | 审计线索，可空 |

索引：`idx_session_user(user_id)`、`idx_session_expire(expire_at)`。

### 3.7 sys_user_permission 用户直接权限

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id | BIGINT PK | 外键 → sys_user.id |
| permission_id | BIGINT PK | 外键 → sys_permission.id |
| apply_id | BIGINT | 来源申请单，可空 |
| granted_at | DATETIME | 授予时间 |

联合主键 `(user_id, permission_id)`，两个外键级联删除。

> 这张表只由审批通过写入，没有对应的"手工勾选"入口。它承担 v0.5 里"例外授予"的角色：不改变角色，直接给某个人加一条权限。

### 3.8 sys_permission_apply 权限申请单

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | 自增 |
| applicant_id | BIGINT | 外键 → sys_user.id，级联删除 |
| target_type | CHAR(4) | `ROLE` 或 `PERM` |
| target_id | BIGINT | 角色 ID 或权限 ID（多态，不建外键，由 Service 校验） |
| apply_reason | VARCHAR(500) | 申请理由，必填 |
| status | TINYINT | 0 待审批 / 1 已通过 / 2 已驳回 |
| approver_id | BIGINT | 审批人，外键 → sys_user.id，`ON DELETE SET NULL` |
| approve_time | DATETIME | 审批时间 |
| approve_comment | VARCHAR(255) | 审批意见（驳回必填） |
| created_at | DATETIME | 提交时间 |

索引：`idx_apply_status(status, created_at)`、`idx_apply_applicant(applicant_id)`。

> 状态只有一个方向：0 → 1 或 0 → 2。没有"已撤回"与"重新打开"，避免状态机复杂化。

## 四、三条核心 SQL

### 4.1 算一个人的全部权限（唯一口径）

```sql
SELECT DISTINCT t.perm_code FROM (
    SELECT p.perm_code
    FROM sys_user_role ur
    JOIN sys_role r             ON r.id = ur.role_id       AND r.status = 1
    JOIN sys_role_permission rp ON rp.role_id = r.id
    JOIN sys_permission p       ON p.id = rp.permission_id AND p.status = 1
    WHERE ur.user_id = ?
    UNION
    SELECT p.perm_code
    FROM sys_user_permission up
    JOIN sys_permission p ON p.id = up.permission_id AND p.status = 1
    WHERE up.user_id = ?
) t
ORDER BY t.perm_code;
```

单点判断：在上面的结果上加 `WHERE p.perm_code = ?`，或取回集合后在内存里 `contains`。两条路径结果必须一致，接口层用后者（一次查询，后续复用）。

### 4.2 角色列表带成员数与权限数

```sql
SELECT r.id, r.code, r.name, r.status,
       (SELECT COUNT(*) FROM sys_user_role WHERE role_id = r.id)       AS member_count,
       (SELECT COUNT(*) FROM sys_role_permission WHERE role_id = r.id) AS perm_count
FROM sys_role r
WHERE (? IS NULL OR r.code LIKE ? OR r.name LIKE ?)
ORDER BY r.id;
```

### 4.3 删除角色前的占用检查

```sql
SELECT COUNT(*) FROM sys_user_role WHERE role_id = ?;
-- > 0 → 返回 409「仍有成员使用该角色」
```

## 五、相互怎么运作

1. **登录**：`sys_user` 校验通过 → 往 `sys_session` 插一行 → 返回 `id` 作为 token。
2. **每次请求**：拦截器用 token 查 `sys_session`，校验未过期、未撤销 → 拿到 `user_id`。
3. **判定**：用 4.1 的 SQL 拿到权限码集合 → 与接口要求的码比对。
4. **配置变更**：改 `sys_user_role` 或 `sys_role_permission` 后，权限集合下一次查询自然变化；同时把该用户的 `sys_session` 批量置 `revoked_at`，强制重新登录。
5. **停用**：`sys_user.status = 0` + 撤销会话，双保险。
6. **申请审批**：提交写 `sys_permission_apply`（status=0）→ 管理员审批 → 通过时把目标角色写入 `sys_user_role`，或把目标权限写入 `sys_user_permission` → 撤销申请人会话 → 重新登录后新权限生效。

## 六、五个设计决策

| 决策 | 理由 |
| --- | --- |
| 直接权限只由审批写入 | 保留"例外授予"能力，但不给管理员手工勾选入口，避免角色被架空 |
| 不再冗余 `user.perm_codes` | 冗余必然出现"改角色后旧权限还在"的问题；一律实时算 |
| 会话落库而不是 JWT | 停用/改角色要能立刻失效，JWT 做不到无状态撤销（除非再建黑名单，反而更复杂） |
| 权限按"功能点 × 操作"拆行 | 一个码对应一个动作，前端按钮、接口注解都能直接引用；不需要解析 "VIEW,EDIT" 这种字符串 |
| 关联表用联合主键 | 天然去重，省一个自增 id，也省一次唯一性校验 |
