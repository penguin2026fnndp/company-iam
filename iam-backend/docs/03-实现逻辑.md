# 实现逻辑（面向功能）

## 一、分层与包结构

不做领域实体、不做继承、不做多态。**一个功能 = 一条 Controller → Service → Mapper 链。**

```
com.iam
├── common
│   ├── Result.java            统一返回 {code,data,message}
│   ├── BizException.java      业务异常（带 code）
│   ├── GlobalExceptionHandler 兜底转 Result
│   ├── AuthInterceptor.java   解析 Bearer、查会话、装上下文
│   ├── RequirePerm.java       注解：@RequirePerm("USER:VIEW")
│   └── SessionContext.java    ThreadLocal：当前 userId / 权限集合
├── auth        AuthController / AuthService / SessionMapper / dto
├── user        UserController / UserService / UserMapper / dto
├── role        RoleController / RoleService / RoleMapper / dto
├── permission  PermissionController / PermissionService / PermissionMapper
└── report      ReportController / ReportService / ReportMapper
```

DTO 跟着功能走：`UserCreateReq`、`UserUpdateReq`、`StatusReq`、`RoleAssignReq`、`PermAssignReq`，不强行复用。

## 二、一次请求的完整链路

```
浏览器
  │  Authorization: Bearer <sessionId>
  ▼
AuthInterceptor.preHandle
  ├─ 无 token            → 401
  ├─ 查 sys_session      → 不存在 / expire_at < now / revoked_at 非空 → 401
  ├─ 查 sys_user         → status = 0 → 401
  ├─ 载入权限集合（4.1 的 SQL）→ 放入 SessionContext
  └─ 读方法上的 @RequirePerm
        ├─ 未标注 → 放行（仅要求登录）
        └─ 标注且集合不含 → 403，返回 requiredPerm
  ▼
Controller  参数校验（@Valid）→ 调 Service
  ▼
Service     业务规则 + 事务（@Transactional）
  ├─ 唯一性 / 存在性 / 不能删自己 / 不能停用自己 / 角色仍有成员
  ├─ 配置类变更：批量撤销相关会话
  └─ 调 Mapper
  ▼
Mapper      XML 里的 SQL，只负责取数/写数
  ▼
Result{code,data,message}
```

**关键点：权限只算一次。** 拦截器算完放进 `SessionContext`，Controller 与 Service 不再重复查库；同一请求内多次判断直接读内存集合。

## 三、四条关键时序

### 3.1 登录

```
POST /api/auth/login {account, password}
  → SELECT * FROM sys_user WHERE account=?
  → 不存在 / BCrypt 不匹配 → 401「账号或密码错误」
  → status=0 → 403「账号已停用」
  → 生成 UUID，expire_at = 今日 23:59:59
  → INSERT sys_session
  → 返回 { sessionId, user, permissions, menus }
```

### 3.2 带权限的业务请求

```
GET /api/users  (Bearer xxx)
  → 会话有效 → userId
  → 权限集合包含 USER:VIEW ?
      否 → 403 { requiredPerm: "USER:VIEW" }
      是 → 查询列表 → 返回
```

### 3.3 越权访问（演示用）

```
李四的 token → GET /api/users
  → 会话有效
  → 权限集合 = {ME:VIEW, OA:DOC:VIEW}
  → 不含 USER:VIEW → 403
```

### 3.4 改角色后立即生效

```
PUT /api/users/3/roles  [EMP, FIN_SPECIALIST]
  → 事务开始
  → DELETE FROM sys_user_role WHERE user_id=3
  → INSERT 新关系
  → UPDATE sys_session SET revoked_at=NOW() WHERE user_id=3 AND revoked_at IS NULL
  → 事务提交

李四下一次请求 → 401（会话已撤销）
李四重新登录 → /auth/me 返回的权限集合已包含 FIN:RPT:VIEW
```

**为什么不用"实时比对权限"来免登录？** 那样会出现"人已经进去了，权限却悄悄变了"的中间态，难以解释。撤销会话 + 重新登录，口径最干净。

## 四、事务边界

| 操作 | 事务范围 | 说明 |
| --- | --- | --- |
| 分配角色 | 删旧 + 插新 + 撤销会话 | 三步必须同成同败 |
| 保存角色权限 | 删旧 + 插新 + 撤销持有人会话 | 同上 |
| 新增用户 | 插入用户 | 单表，可不显式开启 |
| 删除用户 | 删会话 + 删角色关系 + 删用户 | 外键级联即可，但显式写更清楚 |
| 登录 | 插入会话 | 单表 |

并发提示：两个管理员同时改同一角色的权限时，以后提交者为准（覆盖式保存）。演示环境不处理乐观锁，文档里注明即可。

## 五、错误码

| code | 场景 | 前端表现 |
| --- | --- | --- |
| 0 | 成功 | 正常渲染 |
| 400 | 参数错误、停用自己、删除自己、角色不存在 | 表单红字 |
| 401 | 未登录、会话过期、会话被撤销 | 跳登录 |
| 403 | 已登录但缺权限、账号被停用 | 403 页，显示所需权限码 |
| 404 | 用户/角色不存在 | 提示后返回列表 |
| 409 | 账号或角色编码重复、角色仍有成员 | 表单红字 |
| 500 | 未捕获异常 | 通用错误 |

## 六、三层鉴权的关系

| 层 | 由谁做 | 作用 | 能否被绕过 |
| --- | --- | --- | --- |
| 菜单 | `/auth/me` 按权限码过滤后下发 | 不显示无权入口 | 能（改前端） |
| 路由 | 前端守卫 | 地址栏直接访问时拦截 | 能（改前端） |
| 接口 | 拦截器 + `@RequirePerm` | 真正的边界 | 不能 |

汇报时只需强调一句：**前两层是体验，第三层才是安全。**

## 七、功能卡模板（示例：F06 新增用户）

| 项 | 内容 |
| --- | --- |
| 功能 | F06 新增用户 |
| 接口 | `POST /api/users` |
| 权限码 | `USER:ADD` |
| 入参 | `account`（必填，8–32 位，唯一）、`name`（必填）、`phone`（可空，11 位） |
| 校验 | 账号格式、账号唯一（先查再插，捕获唯一键冲突转 409） |
| 出参 | `{ id, account, name, phone, status }` |
| Controller | `Result<UserResp> create(@Valid @RequestBody UserCreateReq req)`，标注 `@RequirePerm("USER:ADD")` |
| Service | 检查重复 → BCrypt 加密 123456 → 插入 → 返回（不创建任何角色关系） |
| Mapper | `SELECT count(*) FROM sys_user WHERE account=?`；`INSERT INTO sys_user(...)` |
| 用例 | ① 正常创建返回 200；② 重复账号 409；③ 缺姓名 400；④ 无 USER:ADD 的账号调用 403 |

其余 19 个功能按同一张卡填写，汇总成《详细设计》。
